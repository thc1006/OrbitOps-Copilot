## What this demo proves

A user asks **"Which beam is degrading and why?"** in natural language. The
system answers based on **live metrics from a running emulator**, not from
LLM imagination. The answer cites:

- the specific degraded beam by id (`beam-1`)
- the metric that proves it (`orbitops_beam_snr_db < 8 dB`)
- a plausible cause grounded in those numbers
- 3 recommended actions
- explicit `unknowns` (epistemic humility)

If the emulator has no degraded metric, the system says
`INSUFFICIENT_EVIDENCE` instead of inventing one. If the question is
out-of-domain (e.g., "What is the weather?"), the system replies `REFUSED`.

## Architecture (three services, in-process or separate)

```text
                  ┌──────────────────────────────┐
                  │ packages/scenarios/          │
scenario JSON ──▶ │   beam-degradation.json      │  (file artifact;
   (file)         │ produced by scenario-generator│   regenerated by CLI)
                  └────────────┬─────────────────┘
                               │ POST /scenario/load
                               ▼
                  ┌──────────────────────────────┐
                  │ ntn-metrics-emulator         │
                  │ - tick t past anomaly window │
                  │ - emit Prometheus exposition │
                  │   on /metrics                │
                  └────────────┬─────────────────┘
                               │ GET /metrics
                               ▼
                  ┌──────────────────────────────┐
                  │ copilot-api  /ask            │
                  │ - is_supported_question?     │  → REFUSED if not
                  │ - scrape /metrics            │  → INSUFFICIENT if down
                  │ - classify (snr_drop /       │
                  │   handover / outage)         │  → INSUFFICIENT if no anomaly
                  │ - FakeLLMProvider.chat       │
                  │ - build CopilotResponse v2   │
                  └──────────────────────────────┘
                               │
                               ▼
                       JSON response cited above
```

The integration is wired via a small `MetricsScraper` Protocol in
`services/copilot-api/src/copilot_api/_retrieval.py`. Production reads
`ORBITOPS_EMULATOR_METRICS_URL` env var; the integration test injects an
in-process `TestClient`-backed scraper.

## One-command demo

```bash
./scripts/demo-beam-quality.sh
```

The script does:

1. preflight (`venv` + `jq` + `curl` + scenario file present)
2. start emulator on `:8000`
3. start copilot on `:8001` with `ORBITOPS_EMULATOR_METRICS_URL=http://127.0.0.1:8000/metrics`
4. wait for `/healthz` on both
5. `POST /scenario/load` with the canonical scenario
6. `POST /scenario/tick {"seconds":90}` (mid-event)
7. `GET /metrics` peek (greps `orbitops_beam_snr_db`)
8. `POST /ask` with the user question
9. validate AC-001 invariants (status, beam-1, SNR, < 8 dB, recommended_actions ≥ 1)
10. tear down (trap EXIT)

Override ports if 8000/8001 are taken: `EMU_PORT=18000 COP_PORT=18001 ./scripts/demo-beam-quality.sh`.

## Running the integration test (no servers needed)

```bash
.venv/bin/pytest tests/integration/test_beam_quality_copilot.py -v
```

This exercises the **same flow in-process** via `TestClient`; no real
sockets, no port conflicts, no docker-compose. Suitable for CI.

## AC-001 invariants verified by both the test and the script

| Invariant | Source |
|---|---|
| `status == "ok"` | AC-001 §Then 1 |
| Summary cites `beam-1` | AC-001 §Then 1 |
| Summary cites `SNR` | AC-001 §Then 1 |
| ≥ 1 `orbitops_beam_snr_db` citation with `value < 8` | AC-001 §Then 2 |
| `evidence.scenario_id == "beam-degradation-001"` | AC-001 §Then 3 |
| `confidence >= 0.5` (FakeLLMProvider returns 0.78) | AC-001 §Then 4 |
| `recommended_actions` non-empty with `title` + `body` | UC1 spec |
| Response time ≤ 5 s (mock provider) | AC-001 §Then 6 |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `port 8000 already in use` | conflict with another service | `EMU_PORT=18000 ./scripts/demo-beam-quality.sh` |
| `make bootstrap` not run | `.venv/bin/uvicorn` missing | `make bootstrap && .venv/bin/pip install -e services/ntn-metrics-emulator services/copilot-api` |
| `status == "INSUFFICIENT_EVIDENCE"` after tick | scraper sees no degraded metric | check `/tmp/orbitops-emulator.log`; verify scenario was loaded; tick value ≥ 60 |
| `status == "REFUSED"` | question not in OrbitOps domain whitelist (`_grounding._DOMAIN_TERMS`) | rephrase using NTN vocabulary (beam / SNR / handover / Doppler / gateway / latency) |
| Test passes but script fails | TestClient bypasses uvicorn; real-server quirks | check that `ORBITOPS_EMULATOR_METRICS_URL` is exported to the copilot uvicorn process |

## Known limitations (Sprint 1)

- **Mock provider only.** `FakeLLMProvider` returns canned analysis. Real
  LLM (Ollama / vLLM / OpenAI-compatible) is Sprint 2 task VS-8.
- **Single anomaly diagnosis.** Classifier picks one anomaly_type by priority;
  if multiple events fire simultaneously, only the highest-priority is
  surfaced. Multi-anomaly fusion is P2.
- **`time_window_seconds` is descriptive, not filtering.** The current
  scraper reads the latest snapshot; it does not query historical PromQL
  ranges. Sprint 2 VS-8 will add range-window querying.
- **No real Prometheus.** Production deployment will swap `HttpMetricsScraper`
  for a `PrometheusQueryScraper` (PromQL queries against Prometheus instead
  of raw `/metrics` scrape) — Sprint 2.
- **No retry / backoff.** If the emulator is briefly unreachable, /ask
  returns `INSUFFICIENT_EVIDENCE` immediately. Sprint 2 may add 1 retry.
- **No streaming response.** Demo is request-response only; no SSE / WS for
  long-running analyses (LLM calls are sub-second with FakeLLMProvider).
- **No authn/authz.** Sprint 1 demo is local-only; Sprint 2+ adds JWT.
- **`/ask` does not currently include `logs_used` evidence.** Only metrics
  are scraped from `/metrics`. Logs (per AC-002) are exercised by `/explain`
  + `/runbook` directly when the caller passes `logs` in the body.
