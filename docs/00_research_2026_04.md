## 1. Executive Summary（為何 OrbitOps Copilot 是高潛力 RunSpace 題目）

1. **題目定位明確且可被驗證**：本專案不是泛用 AI chatbot，也不是另一份 Grafana dashboard，而是**「B5G/NTN 低軌地面站」的雲原生 operations digital twin + LLM Copilot**。輸入是 satellite pass、beam、handover、Doppler、SNR、pod_health 等域內訊號；輸出是 anomaly explanation 與 runbook。每一個 LLM 回答都必須附 metrics / logs evidence block。
2. **正中 2026/04 的真實供應鏈空白**：TASA B5G LEO 計畫已將**衛星酬載（CesiumAstro 1A、YTTEK 1B）**與**用戶終端（Skylark）**指派給公開合約方，但**Ka-band gateway 與地面運維工具鏈在公開資訊中仍是缺口**——這正是 OrbitOps Copilot 切入的位置。
3. **與 3GPP Rel-19（2025-12 凍結）的時序對齊**：Rel-19 將 NTN regenerative payload（gNB-on-board）標準化，本專案的場景模型（`payloadMode: transparent | regenerative`）正是依此設計，**不是猜測**。
4. **與 AI-RAN Alliance 2026 路線一致**：MWC 2026 上 Alliance 公布 4 份藍圖，其中「Platform & Infrastructure Orchestration」是本專案直接命中之分類；Alliance 已成長至 132 會員、33 個 AI demo。
5. **Open-source 紅利剛打開**：NVIDIA 於 2025-10-28 宣布把 Aerial CUDA-Accelerated RAN、Aerial Omniverse Digital Twin（AODT）、Aerial Framework 以 **Apache 2.0** 開源；AODT 排定 2026 年 3 月上 GitHub。**Sionna RT v2.0.1（2026-04-01）**已可在消費級 GPU 上跑 RF ray tracing。本專案 P2 路線可直接接軌，不必自造輪子。
6. **Cloud-native sandbox 訓練／整合測試是真痛點**：B5G 1A 預計 2027 發射、1B 2030，**距發射尚有 12+ 個月**——這正是 pre-flight 整合測試與運維訓練工具最有價值的時間窗。
7. **可在 7–14 天內交付 P0 demo**：MVP 僅做「scenario-generator + ntn-metrics-emulator + copilot-api + digital-twin-ui + Prometheus/Grafana + kind/k3d」，所有元件皆為已成熟、可一鍵部署的 OSS。
8. **可教學、可整合測試、可前景擴充**：同一份骨架可長成（a）大學/法人 NTN 教學沙箱、（b）地面段廠商 pre-field 驗證平台、（c）AI-RAN Alliance 風格的 reference architecture demo。

## 3. 競品與替代方案分析

| 平台 | 主要功能 | 與本專案差異 |
|---|---|---|
| **AWS Ground Station** | 商用 ground station as-a-service：抗議排程、調變、MQTT/S3 落地 | 商用、面向**真衛星實際排程**；非整合測試/訓練平台；不暴露 NTN 域內 metric；不開源 |
| **Azure Orbital**（已部分轉型） | 同上 | 同上；近年策略調整，公開資訊較少 |
| **SatNOGS** | 全球業餘地面站網路、解碼、共享 | 業餘 UHF/VHF；非 B5G/Ka-band；非 NTN domain workflow |
| **Open Cosmos / CGI Insula-like** | 商用 ground segment as-a-service、mission ops | 黑盒、需付費、不可作為 sandbox / 教學 |
| **NVIDIA AODT** | 完整 RAN digital twin（ray-traced channel + Aerial gNB stack + Sionna） | **強大但 GPU 重、整合複雜、聚焦 RAN 而非 NTN ground operations**；本專案以 metrics emulator 切入，把 AODT 留作 P2 |
| **傳統地面站訓練/測試工具** | 多為廠商私有 GUI 或 Excel-driven runbook | 不雲原生、不可 GitOps 部署、無 LLM 解釋 |
| **一般 observability platform**（Datadog、Dynatrace、純 Grafana） | 通用 metrics/logs/traces | 非 NTN domain；無 satellite pass、beam、handover、Doppler 概念；無 anomaly→runbook 自動產出 |

**OrbitOps Copilot 差異化**：

1. **B5G/NTN domain workflow first-class**：scenario、beam、handover、Doppler、payload mode 是一等公民。
2. **Cloud-native deployable sandbox**：kind/k3d 一鍵起；ArgoCD GitOps；Helm/Kustomize 雙軌；Nephio kpt package stub 與 R5 對齊。
3. **Operations twin（不是 air-interface twin）**：聚焦地面段運維事件（beam quality、handover、gateway fallback、pod health），與 AODT 互補不重疊。
4. **LLM evidence-grounded copilot**：所有回答必附 metrics / logs evidence block + scenario ID + timestamp + confidence；不允許自由幻想。
5. **三模合一**：教學沙箱 / 整合測試 / pre-field validation 同一份骨架可服務。

## 4. 技術可行性分析

### P0（7 天內必做）

- `services/scenario-generator/`：產出 satellite pass、beam profile、anomaly injection JSON。
- `services/ntn-metrics-emulator/`：FastAPI + prometheus-client，暴露 `/metrics`，可注入 anomaly。指標：`orbitops_snr_db`, `orbitops_sinr_db`, `orbitops_latency_ms`, `orbitops_packet_loss_ratio`, `orbitops_doppler_residual_hz`, `orbitops_elevation_deg`, `orbitops_handover_state`, `orbitops_beam_id`, `orbitops_gateway_id`, `orbitops_pod_health`。
- `services/copilot-api/`：FastAPI，提供 `/ask`、`/explain`、`/runbook`、`/healthz`，OpenAI-compatible adapter（Ollama / vLLM / LM Studio / remote），所有 response 必附 `evidence` block。
- `services/digital-twin-ui/`：React + Vite + TypeScript + Tailwind + CesiumJS（或 Three.js），顯示 satellite pass、ground station、beam、handover state、anomaly banner、copilot panel。**P0 先建骨架；完整 UI 留 P1**。
- `observability/`：Prometheus scrape config、Grafana dashboard JSON。
- `deploy/`：docker-compose（最快）+ kind/k3d cluster + Kustomize base + Helm chart skeleton。
- 3 個 golden scenario：beam-degradation、handover-failure、gateway-fallback。
- CI：lint、typecheck、unit、no-secrets、k8s manifest validation、docker build dry-run。

### P1（14–30 天）

- 完整 CesiumJS satellite pass 動畫 + 3 beam coverage cone + handover 動畫。
- Voice interface（faster-whisper）整合 `/ask`。
- Loki + Tempo trace 整合（mock logs / mock spans）。
- ArgoCD App-of-Apps 範例。
- Helm chart values 完整化、`helm test` hook。
- 真 Ollama + Qwen3.6-27B 在地推論測試（CPU 夠用之 quantized）。
- Nephio kpt package stub 文件化（不假裝跑 Porch）。

### P2（決賽或長期研究）

- Sionna RT 將 scenario 轉 RF channel coefficients，回填 emulator。
- 真接 srsRAN 或 OAI（NTN branch），讓 emulator 改成 wrapper。
- 真接 Nephio R5 + ArgoCD 完整 GitOps deploy。
- AODT（待 2026 年 OSS 釋出後）整合：把 OrbitOps scenario 轉成 AODT scene。
- Closed-loop：Copilot 建議 → ArgoCD 套用 → 觀察 → 反饋。

### 不做（第一版風險高）

- 真 Ka-band beam steering、真 SDR OTA。
- 真 RF 收發、真天線控制。
- 完整 OAI/srsRAN NTN full stack 整合。
- 完整 O2 IMS lifecycle（只出 stub）。
- 多語意 LLM agent swarm（先單模型 + structured prompt 即可）。
- 自研 ray tracer（直接用 Sionna RT 即可）。

## 6. 風險與緩解

| 風險 | 緩解 |
|---|---|
| 評審期待真 RF/SDR 整合 | 投影片明示 P0 為「metrics emulator + digital twin UI + LLM copilot」；P2 路線寫明 Sionna RT/AODT 接軌 |

| AODT 開源延遲 | 列為 P2，不擋 MVP |
| Helm 4 / Vite 8 / TS 6 / Tailwind 4 重大版本踩雷 | `docs/09_installation_research.md` 列 breaking change；CI 跑 build dry-run |

## 8. 結論

OrbitOps Copilot 切入的是**公開資訊中真實存在的 B5G 地面段運維工具鏈缺口**，技術錨定在已凍結的 3GPP Rel-19 NTN、剛開源的 NVIDIA Aerial 生態、與已穩定發行的 Nephio R5 GitOps 範式上。MVP 範圍嚴格自我設限為 metrics emulator + digital twin UI + LLM copilot + K8s deployment，避開真 RF/SDR/full-stack 風險，可在 7–14 天內交付 demo，並把 Sionna RT/AODT/真 RAN stack 整合留作 P2/P3。
